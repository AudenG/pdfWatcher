# PdfWatcher v1.2.0 — GUI Release

## What's new

### Full WPF desktop interface
PdfWatcher now has a proper window you can open from the tray. Adobe dark theme throughout — deep greys, red accent, Segoe UI.

**Dashboard**
- Live status indicator (Running / Processing / Quota Exhausted) with colour-coded dot
- Stat cards: queue depth, files OCR'd today, files OCR'd this month (of 500 Adobe quota)
- Scrollable recent-activity feed with ✓/✗ result and timestamp per file
- Re-scan Folders button

**Settings**
- Add / remove watched folders with a folder picker
- Backup folder picker with path validation
- Advanced section (collapsed by default — click ▶ Advanced to expand):
  - Performance: Max Concurrent Jobs, Max Search Depth, Backup Retention Days — each with an ⓘ tooltip explaining the setting
  - Adobe PDF Services credentials (Client ID + Client Secret)
- Unsaved-changes banner; Save button; restart notice for settings that require it

**Logs**
- Live log feed streamed from Serilog (up to 500 entries)
- Filter by level: INF / WRN / ERR / FTL with colour-coded rows
- Clear log and Open Log Folder buttons
- Auto-scroll that pauses when you scroll up and resumes when new entries arrive

### Safety: backup / watch folder conflict detection
Three-layer guard prevents a scenario that previously caused a fatal crash at startup:
- Adding a watch folder that contains the backup folder → blocked with explanation
- Browsing to a backup folder inside a watched folder → blocked with explanation
- Typing a conflicting path directly into the backup field and hitting Save → blocked with explanation

### Tray integration
- Double-click tray icon to open/focus the window
- Window close button hides to tray (app keeps running)
- Config hot-reload from the tray now also refreshes the Settings view live

## Bug fixes
- `of 200 quota` label corrected to `of 500 quota`

## Internal
- `AppState` — thread-safe observable state shared between background workers and UI
- `AppStateSink` — custom Serilog sink feeding the Logs view in real time
- WPF + WinForms coexist on the same STA thread; WinForms `Application.Run()` pumps the message loop for both
- All WPF resources loaded at `Application` level before window creation to avoid `StaticResource` resolution failures
